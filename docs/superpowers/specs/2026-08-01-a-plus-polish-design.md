# 科研导航网站 A+ 第二轮优化设计

## 背景

第一轮已经把网站修到可以稳定启动，并完成了 LowDB、登录改密、本地图标缓存、基础安全和测试验证。第二轮目标是在不推翻现有技术栈、不删除现有内容的前提下，把网站从“能用”打磨到“专业、干净、首页更大气”。

用户已批准的视觉方向是：A+，即“清爽科研风 + 首页更大气”。

## 目标

1. 修复第一轮后仍明显影响体验的问题：
   - 前台、后台、登录页中的中文乱码和旧文案。
   - 前台和后台重复的图标渲染函数。
   - 后台弹窗表单中部分字段转义不完整的问题。
2. 升级前台视觉：
   - 首页顶部区域更像科研资源门户，但保持克制、专业、长期耐看。
   - 搜索框、分类导航、链接卡片、图标容器、空状态和加载状态更统一。
   - 保留现有分类、链接和 API 行为。
3. 升级后台基础体验：
   - 登录页恢复正常中文并与整体风格统一。
   - 管理页保留现有布局，但减少原生 `alert()` / `confirm()` 带来的粗糙感。
   - 表单和列表的提示更清晰。
4. 继续保持可维护：
   - 不引入 React、Vue、构建工具或新的大型 UI 框架。
   - 在现有 HTML、CSS、jQuery、Bootstrap、Express、LowDB 结构内做手术式修改。

## 非目标

本轮不做以下事情：

- 不删除、不重排现有分类和链接。
- 不大改数据库结构。
- 不改现有 API 路径。
- 不做完整品牌设计系统。
- 不做公开部署。
- 不引入新的前端框架或复杂构建链路。

## 前台设计

首页采用“大气但不花哨”的科研门户感：

- 顶部导航保持简单，强化站点名称和入口层级。
- Hero 区使用浅蓝、浅紫、白色渐变，增加数据徽标，例如工具数量、分类数量、本地图标缓存状态。
- 搜索框放在视觉中心，尺寸和阴影更突出，让用户第一眼知道可以搜索。
- 分类按钮使用胶囊样式，选中态清晰，hover 状态柔和。
- 链接卡片改为统一圆角、轻阴影、图标容器和更好的间距。
- 图标保持本地路径优先，下载失败的占位图标继续可用。
- 空状态和加载状态改为更自然的中文提示，避免页面显得坏掉。

前台 JavaScript 保持现有数据流：启动时加载分类、链接、公告；搜索和分类筛选仍在前端完成；点击链接仍调用现有点击统计接口。

## 后台设计

后台以“少改结构、提升可用性”为原则：

- 登录页修复乱码，统一标题、说明、输入框提示和错误提示。
- 管理页保留左侧导航和表格管理模式。
- 用轻量 toast 展示成功、失败、校验提示。
- 用站内确认弹窗替代删除、退出等原生 `confirm()`。
- 分类、链接、公告、密码表单继续使用现有接口和字段。
- 后台弹窗模板中所有来自数据库或用户输入的值，在进入 HTML attribute、textarea、select label 或普通文本前统一转义。

## 代码结构

计划只在现有文件附近做小范围修改：

- `public/index.html`：修复乱码文案，调整首页结构需要的少量 class。
- `public/assets/css/style.css`：前台视觉升级主文件。
- `public/assets/js/main.js`：清理重复 `renderIcon`，保持渲染转义和本地图标支持。
- `admin/login.html`：修复乱码和登录页视觉。
- `admin/index.html`：修复乱码，必要时增加 toast/confirm 容器。
- `admin/assets/css/admin.css`：后台登录页、toast、确认弹窗和轻量视觉优化。
- `admin/assets/js/admin.js`：清理重复 `renderLinkIcon`，替换原生提示，补齐表单模板转义。

如果检查中发现某个文件存在严重编码损坏，会优先在原结构基础上恢复可读中文，不做无关重写。

## 数据和接口

不改数据库 schema，不迁移数据。

继续使用：

- `GET /api/categories`
- `GET /api/links`
- `GET /api/announcements`
- `POST /api/links/:id/click`
- 现有后台增删改查接口
- 现有上传图标接口 `/api/upload/icon`

本轮允许修正由本地测试造成的临时点击次数变化，但提交代码时不会把无关运行时数据变化混入设计或实现提交。

## 错误处理和安全

- 前台和后台动态渲染继续使用 HTML 转义。
- 后台表单 attribute 值、textarea 内容和 select label 都必须转义。
- 图标渲染函数只保留一个明确实现，避免后续维护时改错函数。
- 删除、退出等操作保留确认步骤，但用站内确认弹窗展示。
- 上传 SVG 仍保持禁用。
- 生产环境 `JWT_SECRET` 规则保持第一轮结果。

## 测试和验证

实施完成后至少验证：

1. 静态检查：
   - `node --check server/index.js`
   - `node --check public/assets/js/main.js`
   - `node --check admin/assets/js/admin.js`
2. 自动测试：
   - `npm test`
3. 启动验证：
   - `npm start` 能启动。
   - `/api/health` 返回正常。
   - `/api/categories` 仍返回 23 个分类。
   - `/api/links` 仍返回 158 条链接。
4. 前台验证：
   - 首页能正常打开。
   - 搜索、分类切换、链接卡片图标显示正常。
   - 中文文案不再乱码。
   - 空状态和公告内容不会执行 HTML。
5. 后台验证：
   - `admin / admin123` 可登录。
   - 分类、链接、公告弹窗中的已有内容显示正常。
   - 删除和退出确认弹窗可用。
   - 修改密码字段仍使用 `oldPassword / newPassword`。
6. 安全验证：
   - 非图片上传被拒绝。
   - SVG 上传仍被拒绝。
   - 标题、描述、公告中的 HTML 被当作文本展示。

## 交付标准

第二轮完成时应满足：

- 网站本地启动稳定。
- 首页视觉明显比第一轮更专业、更大气。
- 后台不再大量依赖浏览器原生弹窗。
- 主要乱码修复。
- 自动测试和关键手动接口检查通过。
- Git 提交清晰，不混入无关运行时数据或临时文件。
